# FlowBook

คลังกลางเก็บ Flow (Node-RED JSON) ของตู้ชาร์จ พร้อม checklist ทดสอบที่ติ๊กบนเว็บได้
และเก็บผลผูกกับ Flow แต่ละเวอร์ชัน

สร้างมาแก้สองปัญหาพร้อมกัน: หาเวอร์ชันล่าสุดไม่เจอเพราะส่งกันทาง LINE
และไม่รู้ว่า flow เวอร์ชันไหนเคยทดสอบเคสอะไรไปแล้วบ้าง

---

## กติกาข้อเดียวที่ยึดทั้งระบบ

> Flow เวอร์ชันหนึ่งจะขึ้นสถานะ **ปล่อยใช้งาน** ไม่ได้
> ถ้ายังไม่มีผลทดสอบที่ส่งแล้วและผ่านเคสสำคัญครบ

พอที่เดียวที่มี flow "การันตีแล้ว" คือเว็บนี้ ทีมจะเลิกส่งไฟล์กันทาง LINE เอง
โดยไม่ต้องออกกฎบังคับ

---

## สิ่งที่ต้องมีบนเครื่องเซิร์ฟเวอร์

- **Node.js 22 LTS ขึ้นไป** (ต้อง 22.5+) — ดาวน์โหลดจาก nodejs.org แล้วติดตั้งแบบปกติ
- **Git**

ไม่ต้องลงฐานข้อมูลแยก ไม่ต้องลง Visual Studio Build Tools ไม่ต้องใช้ Docker

FlowBook ใช้ `node:sqlite` ที่ติดมากับ Node เองเป็นฐานข้อมูล จึงไม่มี native module
ให้คอมไพล์เลยสักตัว — ซึ่งเป็นจุดที่มักพังบน Windows Server

ทั้งระบบเก็บอยู่ในไฟล์เดียว: `data/flowbook.db`
ส่วนไฟล์ flow จริงเก็บเป็นไฟล์ปกติใต้ `data/flows/<รหัสรุ่น>/<เวอร์ชัน>/`
สำรองข้อมูล = คัดลอกโฟลเดอร์ `data` ทั้งโฟลเดอร์

## ติดตั้งครั้งแรก

```bat
git clone <URL ของ repo นี้> flowbook
cd flowbook
npm ci

copy .env.example .env
```

เปิด `.env` แล้วแก้อย่างน้อยสองบรรทัด:

```ini
SESSION_SECRET="<สุ่มข้อความยาว ๆ อย่างน้อย 32 ตัวอักษร>"
SEED_ADMIN_PASSWORD="<รหัสผ่าน admin ครั้งแรก>"
```

สุ่ม SESSION_SECRET ได้ด้วยคำสั่งนี้:

```bat
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

จากนั้น:

```bat
npm run seed
npm run build
npm start
```

`npm run seed` จะสร้างผู้ใช้ admin และใส่ checklist ตั้งต้นให้ —
Vector 19 เคส และ Vector DC Link 38 เคส 7 กลุ่ม แปลงตรงมาจาก `Flow_Test_CheckList.xlsx`
คำสั่งนี้รันซ้ำได้ ไม่ลบของเดิม

เข้าเว็บที่ `http://<ip เครื่อง>:3000` ล็อกอินด้วยรหัสพนักงาน `admin`
แล้ว **เปลี่ยนรหัสผ่านทันที** ที่หน้า “ผู้ใช้” (ล้างรหัสผ่านตัวเองแล้วตั้งใหม่ตอนล็อกอินรอบถัดไป)

### ข้อควรระวังเรื่อง COOKIE_SECURE

ค่าเริ่มต้นคือ `false` ซึ่งถูกต้องสำหรับการเปิดผ่าน `http://<ip>:3000`

ตั้งเป็น `true` **เฉพาะเมื่อ** เปิดผ่าน `https://` แล้วเท่านั้น
ถ้าตั้ง `true` ทั้งที่ยังเป็น http เบราว์เซอร์จะทิ้ง cookie ทิ้ง แล้วล็อกอินจะไม่ติดโดยไม่มีข้อความ error

## ทำให้รันเป็น Service บน Windows

### วิธีที่ 1 — NSSM (แนะนำ เพราะจัดการง่ายที่สุด)

โหลด [NSSM](https://nssm.cc/download) แตกไฟล์แล้วเปิด Command Prompt แบบ Administrator:

```bat
nssm install FlowBook
```

กรอกในหน้าต่างที่เด้งขึ้นมา:

| ช่อง | ค่า |
| --- | --- |
| Path | `C:\Program Files\nodejs\node.exe` |
| Startup directory | `C:\flowbook` (โฟลเดอร์ที่ clone ไว้) |
| Arguments | `node_modules\next\dist\bin\next start -p 3000` |

แท็บ **I/O** ตั้ง Output/Error ไปที่ `C:\flowbook\logs\service.log` เพื่อดู log ย้อนหลังได้

```bat
nssm start FlowBook
```

คำสั่งที่ใช้บ่อย: `nssm restart FlowBook` · `nssm stop FlowBook` · `nssm edit FlowBook`

### วิธีที่ 2 — PM2

```bat
npm i -g pm2 pm2-windows-startup
pm2-startup install
pm2 start "npm start" --name flowbook
pm2 save
```

### เปิดพอร์ตใน Firewall

```bat
netsh advfirewall firewall add rule name="FlowBook" dir=in action=allow protocol=TCP localport=3000
```

## เปิดให้เข้าจากนอกออฟฟิศ

อย่าเปิดพอร์ต 3000 ออกอินเทอร์เน็ตตรง ๆ ให้วาง reverse proxy คั่นเพื่อทำ HTTPS

ทางที่ง่ายที่สุดคือ [Caddy](https://caddyserver.com/download) ซึ่งขอใบรับรอง Let's Encrypt
ให้อัตโนมัติ สร้างไฟล์ `Caddyfile`:

```
flowbook.yourdomain.com {
    reverse_proxy 127.0.0.1:3000
}
```

แล้วรัน `caddy run` (หรือติดตั้งเป็น service เช่นกัน)

**พอเปิด https ได้แล้ว ให้กลับไปตั้ง `COOKIE_SECURE=true` ใน `.env` แล้วรีสตาร์ต**

ทางเลือกอื่นที่ไม่ต้องเปิดพอร์ตออกเน็ตเลย: Cloudflare Tunnel หรือ Tailscale

## สามเรื่องที่ออกแบบไว้ตั้งใจ

**1. ผลทดสอบเก็บสำเนา checklist ไว้ในตัวเอง**
ตอนกด “เริ่มทดสอบ” ระบบจะ freeze checklist ทั้งชุด ณ ตอนนั้นเก็บไว้กับผลทดสอบ
วันหลังใครแก้ checklist ผลเก่าก็ยังอ่านได้เหมือนเดิมทุกตัวอักษร

**2. ทุกเคสมีรหัสถาวรอยู่เบื้องหลัง**
คุณไม่ต้องกรอกหรือดูมันเลย แต่มันคือสิ่งที่ทำให้ตารางความครอบคลุมเทียบข้ามเวอร์ชันได้
ตอนออก checklist เวอร์ชันใหม่ รหัสนี้จะถูกสืบทอดไป ต่อให้แก้ข้อความหรือสลับลำดับ
ผลเก่าก็ยังจับคู่กับเคสเดิมถูกต้อง

**3. ผลทดสอบที่ส่งแล้วล็อกทันที**
แก้ไม่ได้ ยกเลิกได้อย่างเดียวโดยผู้ดูแลระบบพร้อมเหตุผลที่ถูกบันทึกไว้
เพราะมันคือหลักฐานคุณภาพ ไม่ใช่โน้ตส่วนตัว

## โครงไฟล์

```
src/lib/db.ts          เปิดฐานข้อมูล + ตัวช่วย query
src/lib/auth.ts        session cookie, bcrypt, ตรวจสิทธิ์, audit log
src/lib/queries.ts     คำสั่งอ่าน/เขียนของโดเมน + Test Gate + ตารางความครอบคลุม
src/lib/flow.ts        ตรวจไฟล์ Node-RED, sha256, เขียน zip
src/app/               หน้าเว็บทั้งหมด (Next.js App Router)
src/components/        ชุด UI ธีม Hand-Drawn
scripts/schema.mjs     โครงตาราง ใช้ร่วมกันระหว่างแอปกับ seed
scripts/seed.mjs       เตรียมข้อมูลตั้งต้น
seed-data/             checklist ตั้งต้นที่แปลงมาจาก Excel
data/                  ฐานข้อมูลและไฟล์ flow (ไม่ขึ้น git — สำรองโฟลเดอร์นี้)
```

## ฟอนต์

หน้าเว็บเรียกฟอนต์ Sriracha กับ Mali จาก Google Fonts
ถ้าเซิร์ฟเวอร์หรือเครื่องผู้ใช้ออกอินเทอร์เน็ตไม่ได้ หน้าเว็บจะยังใช้งานได้ปกติ
เพียงแต่ตัวอักษรจะกลายเป็นฟอนต์สำรองของ Windows

ถ้าอยากให้ลายมือขึ้นแม้ไม่มีเน็ต ให้โหลดไฟล์ฟอนต์มาไว้ใน `public/fonts/`
แล้วเพิ่ม `@font-face` ใน `src/app/globals.css` และลบ `<link>` ออกจาก `src/app/layout.tsx`

## เผื่อวันหน้าอยากใช้ git จริง

ไฟล์ flow ถูกเก็บเป็นไฟล์จริงในโครงสร้าง `data/flows/<รหัสรุ่น>/<เวอร์ชัน>/<ไฟล์>.json`
พร้อม sha256 ในฐานข้อมูล ตั้งแต่วันแรก

วันไหนอยากได้ git จริงก็ `git init` ทับโฟลเดอร์ `data/flows` ได้เลย
ไม่ต้องย้ายข้อมูลอะไรทั้งสิ้น

## ยังไม่ได้ทำในเฟสแรก (จงใจ)

- ผูก Serial Number ของตู้ที่ใช้ทดสอบ
- ช่องกรอกค่าที่วัดได้ (kWh หน้าตู้ เทียบกับ meter) แล้วคำนวณ %error
- แยก “Meter / HMI check” ออกเป็นเงื่อนไขผ่านข้อที่สอง
- git เป็น backend จริง
- ส่ง flow ลงตู้จากเว็บ (OTA)

โครงข้อมูลเว้นที่ไว้ให้ทั้งหมดแล้ว เพิ่มทีหลังได้โดยไม่ต้องรื้อ
