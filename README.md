# FlowBook

คลังกลางเก็บ Flow (Node-RED JSON) ของตู้ชาร์จ พร้อม checklist ทดสอบที่ติ๊กบนเว็บได้
และเก็บผลผูกกับ Flow แต่ละเวอร์ชัน

สร้างมาแก้สองปัญหาพร้อมกัน: หาเวอร์ชันล่าสุดไม่เจอเพราะส่งกันทาง LINE
และไม่รู้ว่า flow เวอร์ชันไหนเคยทดสอบเคสอะไรไปแล้วบ้าง

---

## กติกาข้อเดียวที่ยึดทั้งระบบ

> Flow เวอร์ชันหนึ่งจะขึ้นสถานะ **ปล่อยใช้งาน** ไม่ได้
> ถ้ายังไม่มีผลทดสอบที่ส่งแล้วและผ่านเคสสำคัญครบ

พอที่เดียวที่มี flow "การันตีแล้ว" คือเว็บนี้ ทีมจะเลิกส่งไฟล์กันทาง LINE เอง
โดยไม่ต้องออกกฎบังคับ

---

## สิ่งที่ต้องมีบนเครื่องเซิร์ฟเวอร์

- **Node.js 22 LTS ขึ้นไป** (ต้อง 22.5+) — ดาวน์โหลดจาก nodejs.org แล้วติดตั้งแบบปกติ
- **Git**

ไม่ต้องลงฐานข้อมูลแยก ไม่ต้องลง Visual Studio Build Tools ไม่ต้องใช้ Docker

FlowBook ใช้ `node:sqlite` ที่ติดมากับ Node เองเป็นฐานข้อมูล จึงไม่มี native module
ให้คอมไพล์เลยสักตัว — ซึ่งเป็นจุดที่มักพังบน Windows Server

ทั้งระบบเก็บอยู่ในไฟล์เดียว: `data/flowbook.db`
ส่วนไฟล์ flow จริงเก็บเป็นไฟล์ปกติใต้ `data/flows/<รหัสรุ่น>/<เวอร์ชัน>/`
สำรองข้อมูล = คัดลอกโฟลเดอร์ `data` ทั้งโฟลเดอร์

## ติดตั้งครั้งแรก

คำสั่งด้านล่างเป็น **PowerShell** (หน้าต่างสีน้ำเงินที่ Windows เปิดให้เป็นค่าเริ่มต้น)
พิมพ์ทีละบรรทัด อย่าพิมพ์คำอธิบายต่อท้ายบรรทัดคำสั่ง

```powershell
git clone <URL ของ repo นี้> flowbook
cd flowbook
npm ci
npm run seed
npm run build
npm start
```

`npm run seed` ทำสามอย่างให้ในคำสั่งเดียว:

1. สร้างไฟล์ `.env` ให้เอง พร้อมสุ่ม `SESSION_SECRET` ให้เรียบร้อย — ไม่ต้องคัดลอกหรือแก้เอง
2. สร้างผู้ใช้ admin
3. ใส่ checklist ตั้งต้น — Vector 19 เคส และ Vector DC Link 38 เคส 7 กลุ่ม
   แปลงตรงมาจาก `Flow_Test_CheckList.xlsx`

คำสั่งนี้รันซ้ำได้เสมอ ไม่ลบของเดิม

เข้าเว็บที่ `http://<ip เครื่อง>:3000` ล็อกอินด้วยรหัสพนักงาน `admin`
รหัสผ่านเริ่มต้นคือ `flowbook123`

**เปลี่ยนรหัสผ่านทันที** ที่หน้า “ผู้ใช้” — กด “ล้างรหัสผ่าน” ที่บรรทัดของตัวเอง
แล้วตั้งรหัสใหม่ตอนล็อกอินรอบถัดไป

ถ้าอยากกำหนดรหัสผ่าน admin เองตั้งแต่แรก ให้แก้ `SEED_ADMIN_PASSWORD` ใน `.env`
ก่อนรัน `npm run seed` ครั้งแรก

### ข้อควรระวังเรื่อง COOKIE_SECURE

ค่าเริ่มต้นคือ `false` ซึ่งถูกต้องสำหรับการเปิดผ่าน `http://<ip>:3000`

ตั้งเป็น `true` **เฉพาะเมื่อ** เปิดผ่าน `https://` แล้วเท่านั้น
ถ้าตั้ง `true` ทั้งที่ยังเป็น http เบราว์เซอร์จะทิ้ง cookie แล้วล็อกอินจะไม่ติดโดยไม่มีข้อความ error

## ทำให้รันเป็น Service บน Windows

### วิธีที่ 1 — NSSM (แนะนำ เพราะจัดการง่ายที่สุด)

โหลด [NSSM](https://nssm.cc/download) แตกไฟล์แล้วเปิด Command Prompt แบบ Administrator:

```powershell
nssm install FlowBook
```

กรอกในหน้าต่างที่เด้งขึ้นมา:

| ช่อง | ค่า |
| --- | --- |
| Path | `C:\Program Files\nodejs\node.exe` |
| Startup directory | `C:\flowbook` (โฟลเดอร์ที่ clone ไว้) |
| Arguments | `node_modules\next\dist\bin\next start -p 3000` |

แท็บ **I/O** ตั้ง Output/Error ไปที่ `C:\flowbook\logs\service.log` เพื่อดู log ย้อนหลังได้

```powershell
nssm start FlowBook
```

คำสั่งที่ใช้บ่อย: `nssm restart FlowBook` · `nssm stop FlowBook` · `nssm edit FlowBook`

### วิธีที่ 2 — PM2

```powershell
npm i -g pm2 pm2-windows-startup
pm2-startup install
pm2 start "npm start" --name flowbook
pm2 save
```

### เปิดพอร์ตใน Firewall

```powershell
netsh advfirewall firewall add rule name="FlowBook" dir=in action=allow protocol=TCP localport=3000
```

## เปิดให้เข้าจากนอกออฟฟิศ

อย่าเปิดพอร์ต 3000 ออกอินเทอร์เน็ตตรง ๆ ให้วาง reverse proxy คั่นเพื่อทำ HTTPS

ทางที่ง่ายที่สุดคือ [Caddy](https://caddyserver.com/download) ซึ่งขอใบรับรอง Let's Encrypt
ให้อัตโนมัติ สร้างไฟล์ `Caddyfile`:

```
flowbook.yourdomain.com {
    reverse_proxy 127.0.0.1:3000
}
```

แล้วรัน `caddy run` (หรือติดตั้งเป็น service เช่นกัน)

**พอเปิด https ได้แล้ว ให้กลับไปตั้ง `COOKIE_SECURE=true` ใน `.env` แล้วรีสตาร์ต**

ทางเลือกอื่นที่ไม่ต้องเปิดพอร์ตออกเน็ตเลย: Cloudflare Tunnel หรือ Tailscale

## สามเรื่องที่ออกแบบไว้ตั้งใจ

**1. ผลทดสอบเก็บสำเนา checklist ไว้ในตัวเอง**
ตอนกด “เริ่มทดสอบ” ระบบจะ freeze checklist ทั้งชุด ณ ตอนนั้นเก็บไว้กับผลทดสอบ
วันหลังใครแก้ checklist ผลเก่าก็ยังอ่านได้เหมือนเดิมทุกตัวอักษร

**2. ทุกเคสมีรหัสถาวรอยู่เบื้องหลัง**
คุณไม่ต้องกรอกหรือดูมันเลย แต่มันคือสิ่งที่ทำให้สรุปการทดสอบเทียบข้ามเวอร์ชันได้
ตอนออก checklist เวอร์ชันใหม่ รหัสนี้จะถูกสืบทอดไป ต่อให้แก้ข้อความหรือสลับลำดับ
ผลเก่าก็ยังจับคู่กับเคสเดิมถูกต้อง

**3. ฮาร์ดแวร์ผูกกับรุ่นตู้ ไม่ใช่กับแต่ละเวอร์ชัน**
ตั้งครั้งเดียวที่หน้า “รุ่นตู้” แล้วทุกเวอร์ชันของรุ่นนั้นใช้ค่าเดียวกัน
ไม่ต้องกรอกซ้ำทุกครั้งที่อัปโหลด และไม่มีทางที่แต่ละเวอร์ชันจะใส่ไม่ตรงกัน
ถ้าเวอร์ชันไหนไปรองรับฮาร์ดแวร์ต่างออกไป ให้เขียนบอกใน changelog ของเวอร์ชันนั้น

**4. ผลทดสอบที่ส่งแล้วล็อกทันที**
แก้ไม่ได้ ยกเลิกได้อย่างเดียวโดยผู้ดูแลระบบพร้อมเหตุผลที่ถูกบันทึกไว้
เพราะมันคือหลักฐานคุณภาพ ไม่ใช่โน้ตส่วนตัว

## เพิ่มรุ่นตู้ใหม่

ที่หน้า **รุ่นตู้** (วิศวกรทำเองได้ ไม่ต้องรอผู้ดูแลระบบ)

ตอนเพิ่มรุ่นสามารถเลือก **คัดลอก checklist จากรุ่นเดิม** ได้ —
รุ่นใหม่ส่วนใหญ่แตกมาจากรุ่นเก่า คัดลอกมาแล้วค่อยตัดเคสที่ไม่เกี่ยวออก
จะเร็วกว่าพิมพ์ใหม่ทั้งชุด

ถ้าคัดลอกมา ระบบจะเผยแพร่เป็น checklist v1 ให้ทันที เริ่มทดสอบได้เลย
เพราะเนื้อหาผ่านการอนุมัติมาแล้วในรุ่นต้นทาง — เคสทุกข้อได้รหัสถาวรใหม่ของตัวเอง
จึงไม่ปนกับผลทดสอบของรุ่นเดิม
ถ้าเริ่มจากศูนย์ จะเป็นร่างรอผู้ดูแลระบบใส่เคสแล้วกดเผยแพร่

## โครงไฟล์

```
src/lib/db.ts          เปิดฐานข้อมูล + ตัวช่วย query

src/lib/flow.ts        ตรวจไฟล์ Node-RED, sha256, เขียน zip

src/components/        ชุด UI ธีม Hand-Drawn
scripts/schema.mjs     โครงตาราง + migration ใช้ร่วมกันระหว่างแอปกับ seed
scripts/seed.mjs       เตรียมข้อมูลตั้งต้น
seed-data/             checklist ตั้งต้นที่แปลงมาจาก Excel
data/                  ฐานข้อมูลและไฟล์ flow (ไม่ขึ้น git — สำรองโฟลเดอร์นี้)
```

## เปิดเว็บแล้วขึ้น "Application error" ทำยังไง

รายละเอียดของข้อผิดพลาดไม่ถูกแสดงบนหน้าเว็บด้วยเหตุผลด้านความปลอดภัย
`Digest` ที่เห็นเป็นแค่รหัสอ้างอิงไว้ค้นใน log

ขั้นแรกให้รันตัวตรวจสภาพ:

```powershell
cd C:\flowbook
npm run doctor
```

มันจะไล่ตรวจให้ทีละข้อพร้อมบอกวิธีแก้ — Node เวอร์ชัน, node:sqlite,
โฟลเดอร์ที่กำลังทำงานอยู่, `.env`, `SESSION_SECRET`, สิทธิ์เขียนโฟลเดอร์ `data`,
ฐานข้อมูล และผลลัพธ์การ build

ถ้าตรวจแล้วไม่พบปัญหา ให้ดู stack trace จริงด้วยการรันในหน้าต่าง Command Prompt ปกติ:

```powershell
npm start
```

### สาเหตุที่เจอบ่อยที่สุด

**1. Service ไม่ได้ตั้ง Startup directory**
อาการ: รันมือด้วย `npm start` ได้ปกติ แต่พอเป็น service แล้วพัง
เพราะ service จะทำงานอยู่ที่ `C:\Windows\System32` แล้วพยายามสร้างโฟลเดอร์ `data`
ตรงนั้นซึ่งไม่มีสิทธิ์ ให้ตั้ง Startup directory ใน NSSM ให้ชี้มาที่โฟลเดอร์โปรเจกต์

ตอนนี้ FlowBook จะพิมพ์บรรทัดนี้ตอนเริ่มทำงานทุกครั้ง ใช้เช็คได้ทันทีว่าไปถูกที่ไหม:

```
[FlowBook] cwd=C:\flowbook
[FlowBook] ฐานข้อมูล=C:\flowbook\data\flowbook.db
```

**2. Node เก่ากว่า 22.5**
`node:sqlite` ยังไม่มีในเวอร์ชันเก่า ตรวจด้วย `node -v`
ถ้าเป็น 22.5–22.12 ต้องเติม `--experimental-sqlite` — ทางที่ดีกว่าคืออัปเป็น 22.13+ หรือ 24 LTS

**3. โปรเจกต์อยู่ใน C:\Program Files**
บัญชีที่รัน service มักเขียนไม่ได้ ให้ย้ายไปไว้ที่ `C:\flowbook`

**4. ยังไม่ได้สั่ง `npm run seed` หรือ `npm run build`**
`npm run seed` เป็นตัวที่สร้าง `.env` และ `SESSION_SECRET` ให้ ถ้าข้ามไปจะเปิดไม่ขึ้น

**5. `npm run build` ล้มด้วย "database is locked"**
มีอีกโปรเซสเปิดไฟล์ฐานข้อมูลค้างอยู่ — มักเป็นหน้าต่างที่รัน `npm start` ทิ้งไว้ หรือ service ที่ยังทำงาน
ปิดตัวนั้นก่อนแล้ว build ใหม่

**6. ล็อกอินไม่ติดแต่ไม่มี error**
ดู `COOKIE_SECURE` ใน `.env` — ต้องเป็น `false` ตอนเข้าผ่าน `http://`
